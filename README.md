# IronLedger Gyms - Gym Management and Fitness Tracking System

DBMS mini-project: a multi-branch gym chain on **MySQL** (30 tables, triggers, procedures, views, events)
and **MongoDB** (documents whose shape varies or that must expire), used through a **Next.js** web app.

The full step-by-step instructions for Mac and Windows are in `docs/Implementation_Guide.docx`.
This file is the short version.

## Quick start

Run every command from this folder (`gym-management`). Mac: Terminal. Windows: PowerShell.

```
# 1. MySQL: build the database (drops and recreates it, about 20-60 seconds)
mysql -u root -p --execute="source database/mysql/00_run_all.sql"

# 2. MySQL: create the app user ONCE (inside `mysql -u root -p`, choose your own password)
CREATE USER 'gym_app'@'localhost' IDENTIFIED BY 'your_password';
CREATE USER 'gym_app'@'127.0.0.1' IDENTIFIED BY 'your_password';
GRANT SELECT, INSERT, UPDATE, DELETE, EXECUTE ON gym_management.* TO 'gym_app'@'localhost';
GRANT SELECT, INSERT, UPDATE, DELETE, EXECUTE ON gym_management.* TO 'gym_app'@'127.0.0.1';

# 3. MySQL: prove the rules work (expects 35 PASS lines)
mysql -u root -p --execute="source database/mysql/07_tests.sql"

# 4. MongoDB: collections, validation, TTL indexes, sample documents
mongosh "mongodb://127.0.0.1:27017/gym_management_docs" database/mongodb/setup.js
mongosh "mongodb://127.0.0.1:27017/gym_management_docs" database/mongodb/seed.js

# 5. Web app
cd web
cp .env.example .env.local          # Windows: Copy-Item .env.example .env.local
# edit .env.local: MYSQL_PASSWORD and APP_SECRET
npm install
npm run dev                          # open http://localhost:3000
```

Optional end-to-end check of the API (with the app running, from the project root):
`node tools/api_smoke_test.mjs` (38 checks). It changes data, so rebuild with step 1 afterwards.

## Folder map

| Path | What it is |
|---|---|
| `database/mysql/01_schema.sql` | 30 tables with keys, CHECK constraints, generated columns |
| `database/mysql/02_triggers.sql` | helper functions and every business-rule trigger |
| `database/mysql/03_procedures.sql` | stored procedures the API calls |
| `database/mysql/04_views.sql` | dashboards and analytics views |
| `database/mysql/05_seed.sql` | demo data, dates relative to the day you load it (generated by `tools/gen_seed.py`) |
| `database/mysql/06_events.sql` | scheduled jobs: session expiry, auto check-out, plan expiry, overdue invoices |
| `database/mysql/07_tests.sql` | 35 automatic checks of the rules |
| `database/mongodb/` | `setup.js` (collections + indexes) and `seed.js` (sample documents) |
| `web/src/app/api/` | the API layer (Next.js route handlers) - the only code that touches the databases |
| `web/src/app/member, trainer, staff, admin` | the four portals |
| `web/src/lib/` | `mysql.js`, `docs.js` (MongoDB), `api.js` (session + role checks), `otp.js`, `nav.js` |
| `phase2/` | the remaining 25%: SQL, MongoDB script and web files, with `PHASE2_STEPS.md` |
| `docs/` | problem statement, schema, justification, guide, ER diagrams |

## Demo data

The seed loads with "today" = the day you run `00_run_all.sql` (never earlier than 19 Oct 2026),
so visits, streaks and plateaus are always recent. Re-run it on the morning of a demo.
All demo members' active plans run past 31 Dec 2026, so the data also stays valid without a re-run.

Login: enter the phone number; with `DEMO_SHOW_OTP=true` the SMS code and the email code are shown on screen.
A new browser registers itself as a device (email code); after that, "Confirm on this device" stands in for
fingerprint / face unlock. **One login per account at a time**: use separate browsers or private windows
for different accounts, and log out when switching.
